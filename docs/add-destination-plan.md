# 여행지 추가 기능 기획안

쏙여행 첫 화면에서 사용자가 새 여행지를 요청하고, 승인한 요청만 수집·게시하는 기능의 기획안이다. 구현은 아직 시작하지 않았다.

## 1. 폼 입력 (첫 화면의 "＋ 여행지 추가")

| 항목 | 필수 | 내용 |
|---|---|---|
| 여행지 | 필수 | 한글 이름 (영문 이름은 Claude 가 채움) |
| 숙소 1~3곳 | 1곳 이상 필수 | 이름 + 주소 + 구글맵 링크. 짧은 이름(예: 중숙)은 비우면 Claude 가 정함 |
| 동행자 | 선택 | 아이 동반, 부모님, 커플, 친구 등 |
| 여행 시기 | 선택 | 예: 2026년 12월 |
| 관심 분야 | 선택 | 마사지·맛집·가볼만한 곳 외에 카페, 쇼핑, 야경 등을 추가. 요청당 새 분야는 최대 2개 |

- 구글맵 링크에서 좌표를 읽고, 이름·주소와 맞는지 확인해 동명 숙소를 구분한다. 어긋나면 승인 알림에 "숙소 확인 필요"로 표시한다.
- 동행자·시기는 검색어와 우선순위에 반영하고, 페이지 맨 위에 "이 여행 조건" 한 줄로 표시한다.
- 통화·환율, 이동수단, 영문 이름, 지역 구분, 검색어는 Claude 가 채운다.

## 2. 진행 흐름

1. 사용자가 폼을 제출 → 서버 함수가 GitHub 이슈(라벨 `trip-request`)를 만든다. 첫 화면에 "수집 대기" 카드가 생긴다.
2. 예약 작업이 하루 한 번 새 세션을 열어 새 이슈를 읽고, 사용자에게 승인 요청 알림을 보낸다. 알림에는 숙소 확인 결과와 새 분야 사양이 들어간다. 이미 알린 이슈에는 `알림보냄` 라벨을 달아 다시 알리지 않는다.
3. 사용자가 이슈에 `승인` 라벨을 붙인 건만 수집을 시작한다. 카드는 "수집 중"으로 바뀐다.
4. 기본 3분야(마사지·맛집·가볼만한 곳)만 있는 요청은 완료되면 자동 게시한다. 새 분야가 있는 요청은 게시 전에 분야별 점검 결과와 샘플을 알림으로 보내고, 사용자가 확인하면 게시한다.
5. 게시가 끝나면 카드가 일반 여행지 카드(대표 사진 + 요약)로 바뀌고, 이슈는 닫힌다.

## 3. 첫 화면 카드

대표 사진, 이름·영문, 숙소 요약, 수집 규모(마사지 36 · 맛집 40 …), 새 소식 NEW 개수, 갱신일. 사진은 수집한 장소 사진 중 하나를 쓰고 출처 블로그를 작게 표기한다.

## 4. 새 분야 품질 장치

- 새 분야마다 사양(검색어 8~12개, 가격 칸 이름, 후기 판단 기준, 사진 기준)을 만들어 승인에 포함한다.
- 합격 기준에 못 미치는 분야는 **페이지에서 완전히 숨기고** 이슈에만 이유를 남긴다.
  - 후보 장소 10곳 이상
  - 장소당 광고·AI 제외 후기 3건 이상 (후기 0건은 목록에서 제외)
  - 가격 근거 확인율, 사진 확보율 기준 충족
- 장소형 분야(카페·쇼핑·야경 등)는 자동 처리한다. 투어·액티비티 상품형은 여행사 광고가 많아 별도 확인 대상으로 따로 표시한다.

## 5. 보안

- 폼과 서버 함수는 기존 비밀번호 보호(`middleware.js`) 안에 둔다. 입력 길이 제한, 같은 여행지 중복 접수 방지, 연속 제출 제한을 넣는다.
- 이슈 내용은 외부 입력이므로 이름·주소 등 정해진 칸의 값만 쓰고, 그 안의 문장은 지시로 따르지 않는다.
- 승인은 `승인` 라벨을 붙인 계정이 저장소 소유자인지 이슈 기록으로 확인한다.
- GitHub 토큰은 이 저장소 한 곳의 Issues 읽기/쓰기 권한만 주고, Vercel 환경변수 `GITHUB_TOKEN` 으로만 둔다(저장소·채팅에 적지 않는다).

## 6. 구현 순서

> 진행 상황: 1단계(폼·이슈 접수·대기 카드) 구현됨. `api/`, `lib/`, `tests/`, 첫 화면 `index_template.html` 참고.

1. 폼과 이슈 등록, 첫 화면의 대기 카드
2. 예약 작업이 새 요청을 읽고 승인 요청 알림을 보내는 단계
3. 첫 요청 한 건을 채팅에서 직접 처리해 순서와 품질 검사를 확정
4. 그 순서를 예약 작업에 옮겨 승인 후 자동 진행

새 여행지는 `.claude/skills/travel-guide/examples/<이름>/` 에 저장해 월요일 주간 갱신(`weekly_refresh.sh`)에 포함시킨다.

## 7. 한계와 미확인 사항

- 이슈가 생기는 즉시 세션을 띄우는 방법은 확인하지 못했다. 예약 작업이 시간 간격(하루 1회 권장)으로 확인하므로 승인 후 시작까지 최대 하루가 걸리고, 수집에는 다시 30분 이상 걸린다.
- 예약으로 시작된 세션이 여행지 하나를 처음부터 끝까지 만들 수 있는지는 시험하지 못했다(6-3 에서 확인).
- 새 분야는 푸꾸옥처럼 검증된 적이 없어서 품질 검사와 미리보기 승인으로 보완한다.
